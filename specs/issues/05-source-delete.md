**선행 이슈** [지원회사·문체·기타 텍스트 등록 지원](01-source-create.md)

<a name="section-1-0"></a>

## 1.0 이슈 설명

사용하지 않는 지원회사 소스, 문체 및 어투, 기타 텍스트를 삭제할 수 있게 한다.

<a name="section-2-0"></a>

## 2.0 구현 범위

- 기존 소스 및 첨부 삭제와 원본 비동기 정리를 재사용한다.
- 생성 중인 문서와 템플릿에서 참고한 소스의 수명을 정하고 삭제가 기존 결과에 미치는 영향을 검증한다.

<a name="section-3-0"></a>

## 3.0 구현 내역 및 PR 계획

각 변경 요청은 생성·수정 파일을 테스트·문서·스키마·설정을 포함해 최대 5개로 제한한다. 아래 경로는 저장소 루트 기준의 예상 위치다. 신규 클래스 이름은 설계 시 확정한다. 번호 순으로 진행하며 이전 변경 요청이 병합된 뒤 다음 변경 요청을 시작한다. 실제 변경에서 추가 파일이 필요하면 변경 요청을 더 나눈다.

- [ ] PR 1. 신규 유형 삭제와 원본 보존 규칙 검증
  - 예상 생성·수정 파일 2개
  - `back/src/main/java/com/moon/catchup/service/source/SourceManagementServiceImpl.java`
  - `back/src/test/java/com/moon/catchup/service/source/SourceExtendedDeleteTest.java`
  - 없는 소스, 데이터베이스 실패, 첨부 원본 삭제 실패를 검증한다. 기존 구현으로 충족되는 경우 테스트 중심으로 변경한다.

- [ ] PR 2. 삭제 요청 통합 검증과 계약
  - 예상 생성·수정 파일 2개
  - `back/src/test/java/com/moon/catchup/controller/source/SourceExtendedDeleteIntegrationTest.java`
  - `specs/issues/contracts/source-delete.md`
  - 소스 삭제 후 조회 및 원본 접근 차단과 생성 결과의 보존 정책을 검증한다.
  - 이 이슈의 PR 1 병합 후 진행한다.

- [ ] PR 3. 프론트엔드 작업 및 화면 연결 — 신규 소스 삭제 화면
  - 예상 생성·수정 파일 3개
  - `front/src/SourceList.jsx`
  - `front/src/SourceDetail.jsx`
  - `front/tests/05-source-delete.spec.js`
  - 소스 이름이 포함된 삭제 확인과 취소를 제공한다. 삭제 성공 후 목록을 갱신하고 실패 시 소스를 유지하며 오류를 안내한다.
  - 이 이슈의 PR 2 및 화면에서 재사용할 선행 이슈의 백엔드 계약 병합 후 진행한다. 프론트엔드 공통 컴포넌트가 이미 있으면 재사용한다.
  - 구현 후 단위 및 브라우저 통합 검증으로 정상·실패 상황을 확인하고 `npm run lint`, `npm run build`를 실행한다. 브라우저 검증 도구 설정이 추가로 필요하면 선행 준비 변경 요청을 분리해 마지막 프론트엔드 변경 요청의 파일 수를 5개 이하로 유지한다.

<a name="section-4-0"></a>

## 4.0 완료 조건

- [ ] 삭제 확인·취소·성공·실패와 마지막 소스 삭제 후 빈 목록을 확인한다.
- [ ] 실제 백엔드와 프론트엔드를 연결한 브라우저 검증 및 프론트엔드 검사·빌드가 통과한다.
- [ ] 신규 소스를 삭제한 뒤 목록과 상세에서 접근할 수 없다.
- [ ] 다른 소스와 첨부는 유지된다.
- [ ] 소스 참조의 삭제 정책이 계약과 테스트에 반영된다.
- [ ] 기능 구현 후 성공·실패 조건의 단위 테스트와 통합 테스트를 작성·실행하고 관련 테스트를 통과시킨다.
- [ ] 각 변경 요청의 생성·수정 파일 수가 5개 이하이며 컴파일과 해당 단계 검증이 통과한다.

<a name="section-5-0"></a>

## 5.0 미결정 사항

- 생성에 사용한 원본 소스를 삭제했을 때의 정책을 정한다. 생성 입력 복사본과 문서용 이미지 보관을 검토한다.
